- 普通任务: 由INTERACT发起, 给到AGENT侧;
  比如:
  \
  ①SIRI: 假设已经注册了SIRI Daemon(用户可以和通过siri将信息发送给hermes, 并得到回复);
  \
  ②SIRI发消息给HERMS前, 因为siri的语音听写, 准确度很差, github, 容易听写为get up, 所以避免HERMSE理解错误, 需要携带 clean\_input这个skill, 让HERMS知道这个是语音输入的, 可能要理解下
  \
  ③然后因为最终要语音回复给用户, 如果有表格什么的, md格式, 就不适合语音念出来, 那就要 suit\_for\_talk这个skill让HERMS知道, 要适合语音输出
- 定时任务:, 由AGENT自动执行(设定时间, 每x分钟执行一次); 给到 INTERACT侧
  &#x20;  比如:
  \
  ①: 假设已经注册了微信Daemon, 那实时抓去用户微信的数据, 比如有条数据是, "要搜集大家的信息, 需要填写在线文档, 中午12:00完成"; \
  ②因为有chat\_query这个skill,能够查到数据库中有这条消息
  \
  ③因为有todo\_identity这个skill, 检测到了这条消息可能需要列为待办;
  \
  ④随后api解析这个在线文档的网址, 发现需要写姓名, 手机号....等信息\
  ⑤ 然后因为有 todo\_operat, 所以把这个内容, 创建一个Micorsoft TODO的待办: 设定待办的名称, 内容, 截止日期等...... 从而实现 提醒用户的效果!

## 关于Agent

1. 模型无需过于厉害, Hermes + deepseekV4 Flash-200k(opencode-zen免费) 必须能跑! 这是设计底线; \
   就算后面zen不免费, 一个月的调用额度初步验证不超过10¥, 
2. 我们不做底层, Memory(记忆), self-evolution(自我进化,自己写skill), 模型切换.....都给Hermes, OpenClaw\...去弄, 我们只调它们, 我们项目直接把它们看做"Superior AI", 不去研究底层编排(也就是你得多下一个Hermes或者OpenClaw这样的智能体)
3. 没有"LangChain"底层事件流的编排; 全部SKILL驱动!\
   (deepseekV4Flash的模型能力已经足够使用skill来限制事件流了, 没有必要再写底层LangChain了, 灵活和死板只能二选一)

## 整体架构

1. 守护进程(Daemon): 保证能够实时获得微信/修改文件....等消息
2. SKILL驱动: 没有Tools(用skill的script替代), 意味着你可以用Hermes, OpenClaw, Codex, WorkBuddy, 当做底层AI\
   (服了: 为什么Plugin没有和MCP一样的约束啊, HERMES用py, OpenClaw用ts)
3. 插件化: 所有的Daemon, Skill都以插件的方式注入(你当前看到的仓库是壳子, 后续会陆续发插件予以接入, 以实现上述描述的场景)
4. 技术栈
   - 前端: React + tailwind css + shdcn组件
   - 后端: python(fast api)

```
ExposeYourself/
├── backend/          # FastAPI 后端（插件发现、daemon 管理、日志、Skills）
├── frontend/         # React TS 前端（侧栏、PluginPage、日志查看器）
├── plugins/          # 插件 UI 部署产物（expy deploy 自动维护）
├── expy              # CLI 工具（启停、部署、诊断）
└── config.yaml       # 唯一配置文件（端口、插件路径）
```

## 插件机制

每个插件是一个独立目录，包含 `manifest.json` + 可选的 `api/router.py` + `ui/` 前端：

```
1_chat_monitor/
├── manifest.json     # 插件声明（name, ui, api, skills, daemon, logs）
├── api/
│   └── router.py     # FastAPI APIRouter（动态挂载到壳子进程）
├── ui/
│   ├── src/          # React 源码
│   ├── package.json
│   └── vite.config.js
└── provider/         # 插件业务代码
```

壳子在启动时读取 `plugin_paths`，动态加载每个插件的 API 路由和 UI。
